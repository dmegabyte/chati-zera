# Как это устроено

Конфигурация собрана из слоёв. Каждый слой решает одну задачу и не дублирует соседний.

## Слои

| Слой | Файл | Подключается |
|---|---|---|
| Конституция | `AGENTS.md` | автоматически: OpenCode читает `AGENTS.md` из каталога конфига |
| Кардинальное правило | `core-rules.md` | через `instructions`, только в режиме `zera` |
| Стиль | `chati-style.md` | через `instructions` |
| Машинный слой | `AGENTS.local.md` | через `instructions` |
| Роли | `agents/*.md` | автоматически из каталога `agents/` |
| Процедуры | `skills/*/SKILL.md` | по требованию, когда модель вызывает `skill` |
| Настройки | `opencode.jsonc` | локальный файл, в репозиторий не входит |

Порядок важен: конституция задаёт рамку, локальный слой уточняет её под машину,
роли сужают поведение до конкретной работы.

## Роли

Роль — markdown-файл с frontmatter:

```yaml
---
description: одно предложение, когда роль нужна
mode: primary | subagent
model: provider/model
permission:
  read: allow
  edit: deny
---
```

- `mode: primary` — роль, с которой начинается сессия.
- `mode: subagent` — роль, которую вызывает другая роль через `subagent`/`task`.
- `permission` — белый и чёрный списки инструментов. Права дочерней роли не наследуются
  от родительской: она получает ровно то, что записано в её файле.

## Процедуры

Скилл — каталог с `SKILL.md` и, при необходимости, скриптами и тестами. Пока скилл не вызван,
его текст не попадает в контекст: в промпте видно только имя и описание.

Правило: процедура живёт в скилле, инвариант — в `AGENTS.md`. Не наоборот.

## Версии OpenCode

| | V1 (1.18) | V2 (2.x) |
|---|---|---|
| Права | `permission` | `permissions` — массив правил |
| MCP | `mcp` — плоский словарь | `mcp.servers` |
| Агенты | каталог `agents/` | каталог `agents/` |
| Настройки | `opencode.jsonc` | `opencode.jsonc` |

Файлы ролей общие: frontmatter V1 читается обеими версиями. Шаблоны конфига разные —
`templates/opencode.wsl.jsonc` (V1-совместимый) и `templates/opencode.windows.jsonc` (V2).

## Машинный слой

В репозитории нет ничего, что зависит от конкретного пользователя: ни домашних путей,
ни токенов, ни названий проектов. Всё машинное — в двух локальных файлах:

- `opencode.jsonc` — модель, MCP, права, политики провайдеров.
- `AGENTS.local.md` — пути, оболочка, какие MCP реально доступны.

Оба файла в `.gitignore`. Именно поэтому репозиторий можно клонировать на любую машину.

## Пути

Домашние пути в правах ролей записываются как `$HOME/...` — OpenCode раскрывает его
в `read`, `edit` и `external_directory`. В тексте инструкций используется `~/...`.

В shell-правилах `$HOME` не раскрывается, поэтому там применяются относительные команды
или маски.

## Чего здесь нет

- Плагинов: они подключаются локально, потому что зависят от машины и проектов.
- Секретов и OAuth-сессий.
- Проектных ролей и скиллов: их место — в личной конфигурации, а не в общем стандарте.

## Принцип

Все правила следуют ZERA: см. [zera.md](zera.md).
