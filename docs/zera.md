# ZERA — Zero Entropy Architecture

Принцип, из которого выросла вся конфигурация: **система не должна накапливать шум.**

Инструкции для агентов быстро превращаются в свалку: «сейчас в проекте 32 скрипта»,
«обновлено 12 ноября», «временно не трогаем этот файл». Через месяц это врёт, а агент
читает это как правило. ZERA закрывает этот класс проблем.

## Пять инвариантов

### 1. `AGENTS.md` — конституция, а не отчёт

В правилах нет счётчиков файлов, дат изменений, временных списков и заметок «сделано сегодня».
Файл отвечает на вопрос «как работать», а не «что сейчас происходит».

### 2. Инвариант вместо статуса

Формулировка должна оставаться верной завтра: что запрещено, что обязательно, где граница.
Не «пока используем terra», а «основной исполнитель — терра-класс модели; смена согласуется».

### 3. Конкретика — в коде и тестах

Наличие файлов, структуру каталогов и гигиену скриптов проверяет автоматическая проверка,
а не текст инструкции. Правило описывает требование, тест подтверждает факт.

### 4. Устаревшее удаляется

Мёртвые правила не комментируются и не хранятся «на всякий случай». История есть в git;
в рабочем файле остаётся только действующее.

### 5. Один смысл — одно место

Процедура живёт в скилле, правило — в конституции, машинное отличие — в локальном оверлее.
Дублирование смысла означает, что скоро версии разойдутся.

## Как это применяется

| Где | Что разрешено | Что запрещено |
|---|---|---|
| `AGENTS.md` | правила и границы | статусы, счётчики, временные заметки |
| `README.md` | описание, установка, принципы | история изменений, текущее состояние проекта |
| `docs/` | объяснение устройства | отчёты «что сделали на этой неделе» |
| тесты и скрипты | проверка структуры и гигиены | хранение правил в тексте |
| скилл `zera-cleanup` | разовая уборка репозитория | постоянное «поддерживание порядка» вручную |

## Пример

Плохо:

```markdown
## Текущее состояние
- 32 скрипта в корне, 7 временных файлов
- 12 ноября: переименовали репозиторий
- временно: плагины лежат в git
```

Хорошо:

```markdown
## Роли
Роли лежат в agents/. Каждая — markdown с frontmatter: mode, model, permissions.
Список актуальных ролей смотрится командой, а не по тексту инструкции.
```

## Чеклист перед изменением правил

1. Это правило или отчёт? Отчёт — не сюда.
2. Останется ли формулировка верной через месяц?
3. Можно ли проверить это тестом вместо текста? Если да — проверка в тест.
4. Не дублирует ли это то, что уже сказано в другом слое?
5. Удалено ли то, что заменено?

## Связь со скиллом

`skills/zera-cleanup/` — разовая процедура: разложить скрипты по каталогам, обновить конфиги,
добавить проверку гигиены. Принцип ZERA действует всегда, скилл — когда нужна уборка.
