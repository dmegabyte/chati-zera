# chati-agent

Агентская конфигурация для [OpenCode](https://opencode.ai), в которой у агента есть границы:
он не выдумывает факты, не раздувает контекст и не выходит за пределы задачи.

Правила, координатор `ЧАТИ`, исполнитель, исследователь и принцип ZERA в одном репозитории.
Работает на Linux/WSL и Windows, на OpenCode V1 и V2.

## Зачем это

Агент без правил ведёт себя предсказуемо плохо: отвечает по памяти вместо источников,
тащит в контекст лишнее, чинит попутные баги и объявляет задачу готовой без проверки.

Здесь это закрыто тремя слоями: конституция с границами, роли с узкой зоной
ответственности и процедуры, которые подключаются только по необходимости.

## Быстрый старт

Linux / WSL:

```sh
git clone https://github.com/dmegabyte/chati-agent ~/.config/opencode
cd ~/.config/opencode
./scripts/bootstrap.sh
```

Windows (PowerShell):

```powershell
git clone https://github.com/dmegabyte/chati-agent $env:USERPROFILE\.config\opencode
cd $env:USERPROFILE\.config\opencode
.\scripts\bootstrap.ps1
```

Скрипт создаёт `opencode.jsonc` и `AGENTS.local.md` из шаблонов и подставляет пути.
Существующие файлы он не перезаписывает.

Дальше:

1. `opencode auth login` — вход в провайдера моделей.
2. `opencode api get /api/agent` — проверка: должно быть 3 роли плюс встроенные.
3. `opencode run "Ответь одним словом: OK"` — сквозная проверка.

Модель в шаблоне не задана: OpenCode использует выбранную вами. Если нужна конкретная —
добавьте `model` в `opencode.jsonc`.

## Что внутри

| Слой | Файлы | Зачем |
|---|---|---|
| Правила | `AGENTS.md` | 9 разделов: фокус, стиль, evidence, инструменты, границы, проверка, делегирование, git, ZERA |
| Кардинальное правило | `core-rules.md` | без источника нет факта |
| Стиль | `chati-style.md` | короткий вывод, простой язык |
| Роли | `agents/` — 3 файла | координатор, исполнитель, исследователь |
| Процедуры | `skills/` — 1 каталог | ZERA-уборка структуры |
| Шаблоны | `templates/` | конфиг для Linux и Windows + локальный оверлей |
| Установка | `scripts/bootstrap.*` | заполнение конфига на новой машине |

## Роли

| Роль | Режим | Когда нужна |
|---|---|---|
| `ЧАТИ` | primary | интерфейс и координация: простые задачи делает сам, помощников зовёт по делу |
| `executor` | subagent | ограниченная реализация: код и локальные проверки |
| `evidence-scout` | subagent | непонятно, какие источники читать: возвращает карту доказательств |

Встроенные роли OpenCode (`explore`, `general`) остаются доступны и не требуют настройки.
Свои роли добавляются одним markdown-файлом — см. [docs/customize.md](docs/customize.md).

Подробно: [docs/roles.md](docs/roles.md).

## Процедуры

| Скилл | Когда применять |
|---|---|
| `zera-cleanup` | реструктуризация репозитория и гигиена скриптов |

Остальные процедуры — рабочий процесс конкретной команды: они не входят в общий стандарт.
Своя процедура добавляется каталогом `skills/<имя>/SKILL.md`.

Подробно: [docs/skills.md](docs/skills.md).

## Как это работает

1. `opencode.jsonc` подключает файлы правил через `instructions` и задаёт модель.
   `AGENTS.md` из каталога конфига OpenCode читает сам.
2. Роли лежат в `agents/*.md` — это markdown с frontmatter: описание, режим, права.
3. Скиллы лежат в `skills/<имя>/SKILL.md` и подгружаются по требованию, а не висят в контексте.
4. Машинные отличия — в `AGENTS.local.md`: пути, оболочка, доступные MCP.

Правила не привязаны к конкретному MCP-серверу. Если поиска по документации нет,
используется `read` / `grep` / `glob` по локальным файлам и `webfetch` для внешних источников.

Подробно: [docs/architecture.md](docs/architecture.md).

## Обновление

```sh
cd ~/.config/opencode && git pull
```

Локальные файлы `opencode.jsonc` и `AGENTS.local.md` не отслеживаются, поэтому обновление
не затрагивает вашу модель, MCP и пути. Если изменился шаблон конфига, новые поля
переносите вручную — bootstrap существующие файлы не перезаписывает.

## Настройка под себя

- **Модель** — `model` в `opencode.jsonc` или строкой `model:` в файле роли.
- **Свой MCP** — `opencode mcp add <имя> --global --url <url>`; правила менять не нужно.
- **Своя роль** — добавить `agents/<имя>.md` с frontmatter.
- **Своя процедура** — добавить `skills/<имя>/SKILL.md`.
- **Секреты** — только `{env:...}` или `{file:...}` в локальном конфиге, не в репозитории.

Пошагово: [docs/customize.md](docs/customize.md).

## ZERA — Zero Entropy Architecture

Главный принцип, из которого выросли остальные правила: система не должна накапливать шум.

- **`AGENTS.md` — конституция, а не отчёт.** Никаких счётчиков файлов, дат и временных списков.
- **Инвариант вместо статуса.** Правило должно оставаться верным завтра.
- **Конкретика — в коде и тестах.** Структуру проверяет тест, а не текст инструкции.
- **Устаревшее удаляется.** Мёртвые правила не комментируются: история есть в git.
- **Один смысл — одно место.** Процедура в скилле, правило в конституции, машинное — в оверлее.

Подробно с примерами: [docs/zera.md](docs/zera.md).

## Принципы

- **Факт без источника не факт.** Ссылка на файл, документацию или вывод инструмента обязательна.
- **ZERA.** Система не накапливает шум: правила — инварианты, конкретика — в тестах.
- **Минимальное делегирование.** Один помощник, максимум два на независимых задачах.
- **Проверка до готовности.** Задача не считается выполненной без теста, smoke-проверки или явного ограничения.

## Требования

- OpenCode 1.18+ (V1) или 2.x (V2).
- Провайдер моделей, доступный вашему аккаунту.
- Git и Bash/PowerShell для установки.
