# Как участвовать

Репозиторий открыт: можно брать целиком, копировать отдельные роли и скиллы или предлагать
улучшения.

## Что приветствуется

- Правила, которые закрывают реальный сбой в работе агента.
- Роли с узкой зоной ответственности и явными границами.
- Процедуры, которые экономят шаги, а не описывают очевидное.
- Исправления в документации: неточность, мёртвая ссылка, устаревшее утверждение.
- Новые примеры «плохо / хорошо».

## Что не принимается

- Секреты, токены, cookie, приватные URL.
- Данные конкретных проектов, клиентов и компаний.
- Отчёты о состоянии («сейчас в проекте N файлов», «обновлено 12 ноября») — это нарушает ZERA.
- Реклама инструментов без описания задачи, которую они решают.

## Порядок

1. Форк или ветка.
2. Одно изменение — одна причина. Не смешивайте правку правила с переписыванием документации.
3. Проверьте, что примеры и ссылки рабочие.
4. Откройте pull request: что меняется, какую проблему закрывает, как проверить.

## Требования к формулировкам

- Правило должно оставаться верным через месяц. Если это статус — ему не место в правилах.
- Один смысл — одно место: процедура в скилле, инвариант в `AGENTS.md`.
- Короткие абзацы, живой язык, без канцелярита.
- Если правило можно проверить тестом — лучше тест, чем текст.

Подробно о принципе: [docs/zera.md](docs/zera.md).

## Проверка перед отправкой

```sh
opencode api get /api/agent     # роли загружаются без ошибок
opencode mcp list               # MCP не сломан
```

Если меняли скилл — прогоните его на тестовом проекте, а не на рабочем.
